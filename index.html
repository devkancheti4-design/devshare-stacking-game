Chapter 1 — Meet the Game

Before building, let us understand what a game actually is to a computer.

Every game is only three things

It looks like magic, but every arcade game — Mario, Flappy Bird, our stacking game — repeats three steps about 60 times per second:

  1. Input — did the player tap, click or press a key?
  2. Update — move things, apply gravity, check collisions, add score.
  3. Draw — erase the screen and paint everything at its new position.

That circle is called the game loop. Movement is an illusion: draw a block at x=100, erase, draw it at x=102, erase, draw at x=104… your eye sees smooth motion.

The game we are building

  • A cute animal sits on a tower 🐢
  • Tap to lay a block underneath — the tower grows and lifts the animal
  • Land a block neatly and you get a Perfect; three in a row = a combo
  • Miss badly and the tower wobbles and it is game over

Every piece of that is built in the chapters ahead — and each chapter's code runs live.

Chapter 2 — Your First Canvas

The <canvas> is a rectangle you can paint on with code. It is where the whole game lives.

Two lines to get a paintbrush

The setup every game starts with

  
ctx (short for context) is your paintbrush. The main commands:

  
    
    
  • ctx.fillStyle = "skyblue" — choose a colour
    • 
    
  • ctx.fillRect(x, y, width, height) — paint a rectangle
    • 
    
  • ctx.beginPath(); ctx.arc(x, y, radius, 0, 7); ctx.fill() — paint a circle
    • 
    
  • ctx.clearRect(0, 0, W, H) — erase everything
    • 
  

  
📐 Important: in canvas, y grows downwards. (0,0) is the top-left corner,
  so a bigger y means lower on the screen. Every beginner trips on this once — now you will not.


  
Example — paint the game background

  a sunset colour like "#ff9a76".


  

  
  







  
Chapter 3 — The Game Loop

  
One function that runs 60 times a second turns a still picture into a game.


  
requestAnimationFrame

  
You write a function that draws one frame, and at the end you ask the browser to call it again:

  
The loop

  
The browser now calls frame about 60 times per second, perfectly timed with your
  screen. Inside it you always do the same two things: erase, then draw everything at its new place.


  
Example — clouds drifting across the sky

  

  
💡 If you forget clearRect, the old frames stay on screen and everything

Chapter 5 — Gravity & Falling

  
Real-feeling movement comes from two numbers: position and velocity.


  
The three lines of physics

  
Gravity in 3 lines

  
    
    
  • Position (y) — where the block is now
    • 
    
  • Velocity (vy) — how fast it moves each frame
    • 
    
  • Gravity — a small amount added to velocity every frame, so it speeds up as it falls
    • 
  

  
That is genuine physics: gravity changes speed, speed changes position. Bouncing is
  one more line — when it hits the ground, flip the velocity and shrink it:
  vy = -vy * 0.6.


  
Example — bouncing eggs

  

  
📝 Practice: set gravity to 0.1 for moon physics,
  or bounce to 0.95 for a super-bouncy ball.


  

  
  







  
Chapter 6 — Tap to Play

  
A game without input is a cartoon. Let us hand the controls to the player.


  
One action, three devices

  
Your game should work with a mouse, a finger and a keyboard. The modern way is
  pointerdown, which covers both mouse and touch:

  
Input for everyone

  
Notice both events call the same function. Never write your game logic twice —
  write drop() once and let every input trigger it.


  
Example — tap to lay a block

  

  
💡 e.preventDefault() on touch stops the browser from

Chapter 7 — Stacking & Collision

  
This is the heart of the game: blocks that land on each other and build a tower.


  
The tower is just an array

  
Every block is an object {x, y, w} and the tower is a list of them:

  
The tower


  
Did it land? — overlap maths

  
A falling block lands when its bottom reaches the top of the block below. Then you check
  how much they overlap horizontally:

  
Overlap check

  
If the overlap is zero the block missed completely — game over. If it is small, the tower
  gets narrower. This single idea (compare edges of two rectangles) is how nearly all 2D
  collision works.

Chapter 8 — Score, Perfect & Combo

  
Rules turn movement into a game. Rewarding skill is what makes players say "one more try".


  
Reward precision

  
Measure how far the new block landed from perfectly centred:

  
Perfect detection

  
    
    
  • Perfect — within a few pixels: bonus points and a flash
    • 
    
  • Combo — three perfects in a row: a special mode (in the original game, "Shooty Mode")
    • 
    
  • Miss — reset the combo, shrink the tower
    • 
  

  
Notice the pattern: the game keeps a few numbers (score,
  combo, best) and every landing updates them.
  That is all a scoring system is.


  
Example — scoring with combos

  

  
📝 Practice: make Perfect easier by changing the tolerance from 6 to 15 pixels,
  or give 5 points per perfect instead of 3.


  

  
  







  
Chapter 9 — Juice: Particles & Shake

  
"Juice" is what game developers call the small effects that make a game feel alive. Same rules, ten times more fun.


  
Particles = tiny objects in an array

  
Confetti burst

  
Each frame: move every particle, shrink its life, delete the dead ones. The exact same
  loop you already know from the falling block — just with many little ones.


  
Screen shake in two lines

  
Before drawing, nudge the whole canvas by a random amount, then put it back:

  
Screen shake


  
Example — juice it up

  

  
💡 Juice is the cheapest upgrade in game development. The same game with particles,
  shake and a pop animation feels professionally made — and it is about 20 extra lines.
